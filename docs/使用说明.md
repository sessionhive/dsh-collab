# 使用说明（dsh-collab / dsh-workbench-core 0.1.0）

> 面向使用者的完整手册：安装 → 首次配置 → 日常协作 → 看板/设置 → 记忆与学习 → 升级与排错。
> 英文版：[USAGE.md](USAGE.md) · 主 README：[../README.md](../README.md)

---

## 0. 一句话

让**多个 AI 会话**像一个小团队：**工单派单 → 转交接力 → 回执验收**，记忆落在文件里，换会话不失忆。

## 1. 核心概念（先看这 5 个词）

| 词 | 含义 |
|---|---|
| **会话（session）** | 一个 AI 窗口；每个窗口绑定一个“会话档案”（card/summary/memory）。 |
| **主负责人（owner）** | 谁接到需求谁负责：判断哪些自己做、哪些派出去，最终验收与交付。 |
| **工单（order）** | `dhNNN` 一张单，记录派单/进度/交接/验收/终态；一任务一单。 |
| **flow（接力顺序）** | 单上写明由谁接棒，如 `[后端, 测试]`；交接自动唤醒下一棒。 |
| **交接（handoff）** | 当前持有者把单交给下一棒（可打回 back）；最后一棒交回主负责人。 |

三固定动作：**派单**（建单+发首棒）、**转交**（handoff）、**回执**（最后一棒交回 + owner 验收关单）。

## 2. 安装

### 2.1 独立 DSH（桌面版/Web）

1. 把包解压到 profile 的 `node_modules`：
   ```bash
   tar -xzf dsh-workbench-core-0.1.0.tgz --strip-components=1 \
     -C <DSH_HOME>/profiles/<profile>/node_modules/dsh-workbench-core
   ```
2. 在 profile 的 `cordis.patch.yml` 里 `insert`：
   ```yaml
   - insert:
       - id: workbench-core
         name: dsh-workbench-core
         config:
           dataRoot: '/绝对路径/.dsh'    # 协作数据落在哪
   ```
3. **重启 DSH**（插件在引擎启动时加载）。
4. 打开 设置 → 会话协作，能看到 3 个 tab 即成功。

> 没有外壳也能用：插件自动用 `dataRoot` 建目录、自动索引、内置看板。

### 2.2 与本机工作台共存

同一台机器上可以多个 DSH 实例共用插件源码，但**各自配自己的 `dataRoot`**，数据互不污染。

### 2.3 安装后自检

- 设置 → 其他设置 → **一键自检**（不依赖外壳，外部 DSH 也可用）
- 失败项会写原因；也可看 `_meta/logs/plugin.log`。

## 3. 首次配置

1. **建会话**：设置 → 会话协作 → `+ 新增协作会话`。填：协作 id（英文小写，如 `backend`）、名称、会话（自动新建或选已有）、工作区、分组、技能（可不选，会自动建）。
2. **建分组**（可选）：如“协作开发”，把会话放进去。
3. **打开看板**：设置 → 其他设置 → `打开看板`；或直接访问 `http://127.0.0.1:<引擎端口>/plugins/workbench-core/board`。
4. **主题/语言**：看板右上角 `☀/🌙` 与 `中/EN`，选择会持久化。

### 3.1 每个会话的“身份三件套”

```
<dataRoot>/agents/<会话id>/
├─ card.json      身份/职责/边界/技能
├─ summary.md    在做 / 下一步 / 卡点 / 指针
└─ memory/       按日期的结论（带来源）
```
开场时该会话会收到一条 **seed**：读 card + summary + 看板；无单就回执，有实质工作才写回。

## 4. 日常协作（一单三棒完整示例）

**场景**：命令 → 后端 → 测试

1. **给命令发需求**：
   > “用 Go 写一个简单 HTTP 接口，并测试，最后把测试报告给我。”
2. **命令判断归属**：
   - 实现归后端、测试归测试、调度与验收归自己 → **不自己动手**。
   - 建**一张**单：`wb_write(task)`，`flow=[后端, 测试]`，`write_scopes` 声明写入范围。
3. **后端接单**：自动 ack → 实现 + 自测 → `submit` → `handoff` 给测试（自动唤醒测试）。
4. **测试接单**：自动 ack → 独立验证 → 写证据 → `handoff` 回命令（不 close）。
5. **命令验收**：核证据（不重跑全套）→ `verify` → `close done` → 汇报交付。

**你会在看板看到**：一张单、链路卡片（派单→接管→交接→接管→回执→验收）、每棒耗时、证据路径。

### 4.1 只有一个会话怎么办

- 也可以只用一个会话：它既当 owner 又当执行者，跳过 flow，直接干活 → `note` 写回 → 关单。
- 多会话不是必须，**文件记忆与工单纪律**本身就是收益。

### 4.2 卡住了怎么办

| 现象 | 处理 |
|---|---|
| 单子一直“等待/已投递” | 接单方没 ack；stale 窗口后 owner 会收到通知，接单方会被**再唤醒一次** |
| 接单方答非所问 | owner 用 `comment` 补充要求（同一张单，不要另开单） |
| 做错方向 | `reject` 或 `handoff back` 打回上一棒 |
| 会话被归档 | 设置页 `重新绑定`（生成接力摘要 + seed）或 `交接` |

## 5. 工具详解（AI 用的）

### wb_read

| action | 说明 |
|---|---|
| `check` | 三项检查（数据根/索引/配置摘要） |
| `scene` | 某会话的 card + summary + 最近记忆 |
| `order` | 某工单 + 事件 + 时间线 + 指标 |
| `board` | 看板数据（会话/在途单/事件） |
| `search` | 轻检索（query/scope/since/limit），不建向量索引 |

### wb_write

| action | 关键参数 | 校验 |
|---|---|---|
| `note` | text、refs | refs 必填、≤2KB、只能写自己目录 |
| `progress` | orderId、text | 未关闭；首次自动补 ack |
| `comment` | orderId、text | 任何角色可写同一张单 |
| `task` | to、task、flow/collaborators、loc、accept、forbid、write_scopes | 同 hash 未关闭硬拒绝；必填项缺失警告 |
| `submit` | orderId、note、refs | 证据非空 |
| `verify`/`reject` | orderId、note、refs | 仅 owner |
| `handoff` | orderId、to、kind(next/back)、note、refs | 目标在 flow 或 owner；非最后一棒禁止 close；重复交接去重 |
| `close` | orderId、status(done/blocked/cancelled)、note、refs | 证据可达；done 时自动补记忆 |
| `cancel`/`reopen` | orderId、note | 权限 |

> 常用口径：**先 ack（progress 一行）**；**有下一棒必须 handoff**；**最后一棒交回 owner**；**别 sleep/轮询等别的会话**。

## 6. 看板

| 区块 | 内容 |
|---|---|
| KPI | 会话数 / 在途单 / 今日完成 / 今日事件+违规 / 近 7 天返工率 / 单均时长 / stale 率 |
| 会话表 | 会话名、在做、下一步、卡点、在途单；点开抽屉看摘要与最近单 |
| 协作在途 | 在途单卡片（flow 步骤条：已完成/当前/待办） |
| 协作单 | 全部单（近 20，可筛选），点开**详情抽屉** |
| 详情抽屉 | 顶部状态/owner/总时长；每棒链路卡（动作/时间/耗时/证据）；事件时间线；打开单文件/复制路径 |
| 最近事件 | 中文类型（派单/送达/接单/进度/提交/转交/验收/关单/说明/回执）+ 筛选 |
| 学习 | 当前版本信号 / 历史（仅参考）/ 自动调整记录 |
| 黑板 / 全局规则 | 只读展示 |

## 7. 设置页

| Tab | 内容 |
|---|---|
| 全局规范 | 使用者可编辑的全局规则（底层宪法内置、不可见） |
| 会话协作 | 会话卡片（编辑/交接/解绑/归档/⋮菜单）；分组；搜索 |
| 其他设置 | 启动预检、引擎端口、运维（自检/看板/事件日志）、行为预算、超时催办、自动索引、高级清理 |

> 默认保守：**token 阈值提醒 / 超时催办默认关闭**；学习自动应用默认开启（只改插件默认值，可回退）。

## 8. 模板自定义

| 模板 | 覆盖位置 |
|---|---|
| 入场 seed | `<dataRoot>/shared/templates/seed.md` |
| 派单文档 | `<dataRoot>/shared/templates/dispatch.md` |
| 交接/接管段头 | 插件自动生成（不可改） |

改完直接生效（下次使用），无需重启。

## 9. 记忆、索引与时间线

- 结论：`agents/<id>/memory/<日期>/note.md`（≤2KB；超出轮转 `note.detail.md`）
- 工单记忆：`memory/<日期>/dhNNN.md`
- 索引：`memory/INDEX.md`（时间线，≤120 行，更早按月折叠）
- 会话事件：`sessions.jsonl`（entry/handover/accept/end）
- 工单完成索引：`collab/done-index.md`
- 规则：**只有本会话能写自己的 agents 目录**；跨会话写协作单/黑板。

## 10. 学习机制

- 采集：失败/超时/违规/中断/反馈 → `_meta/learn/signals.jsonl`
- 分类：缺证据 / 越权写 / 身份错 / 交接 / 超时 / 环境坑
- 周报：`_meta/learn/weekly.md`（返工率、stale 率、单均时长、主要失败模式）
- 自动应用：候选（≥3 样本、≥30%）→ 观察 7 天 → 才注入；每周 ≤3 项；带版本可回退；**不碰宪法**
- 关闭：`config.learn.autoApply=false`

## 11. 升级 / 备份 / 回滚

1. 备份：整包快照 `dataRoot` + 插件目录（或 `工具\统一备份.mjs`）
2. 升级：覆盖 `node_modules/dsh-workbench-core` → **重启** → 自检
3. 回滚：换回旧 tgz，`schemaVersion` 迁移向下不保证（升级前先备份）
4. 版本一致性：`/plugin-info` 会显示「运行版本 vs 磁盘版本」

## 12. 排错速查

| 现象 | 排查 |
|---|---|
| 设置页看不到会话协作 | 插件未加载：检查 cordis insert、重启、`/plugin-info` |
| 看板空白/旧数据 | 引擎端口变化？用 `打开看板` 重新取地址；重启加载新版本 |
| 交接失败：未选择工作区 | 表单里选工作区，或配 `config.defaultCwd` |
| close 被拒：证据不可达 | refs 改绝对路径/确认文件存在 |
| 归档会话无法唤醒 | 正常设计：重新绑定/交接，归档是冻结 |
| 外部 DSH 无「一键自检」结果 | 用插件内部自检（`/ops/selfcheck`），不依赖外壳 |

## 13. 边界与隐私

- 只写路径引用，不写密钥/账号/私人内容
- 数据全在 `dataRoot`，不上传；插件不做网络回传
- 只读展示：别人的记忆只读，跨会话只写协作单/黑板

## 14. 明确不做

自动换会话、后台 AI 循环、向量检索、多用户权限、新手引导、自动改宪法/用户规则。
